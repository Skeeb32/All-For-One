# Contributing

Thanks for helping improve All For One. Keep changes focused and preserve the shared design tokens, navigation patterns, and route structure.

## Before opening a pull request

1. Install dependencies with `npm install`.
2. Run `npm test`, `npm run lint`, and `npm run build`.
3. Check the changed route at a narrow mobile width and a desktop width.
4. Label synthetic data and distinguish planned integrations from connected services.
5. Never commit credentials, private user data, or unreviewed generated files.

## Reporting a bug

Include the route, expected behavior, actual behavior, browser, viewport size, and steps to reproduce. Remove private data from screenshots and logs.

## Pull requests

Describe the user-facing change, list the checks you ran, and note any integration that still requires credentials or backend setup. Avoid adding controls that do not perform their stated action.
